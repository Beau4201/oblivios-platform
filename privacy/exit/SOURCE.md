## Patches

| Patch | Subject | Why it diverges from upstream |
| --- | --- | --- |
| `packages-modules-connectivity/0001` | Connectivity: allow the OEM network preference on phones | Upstream restricts the production values of `OemNetworkPreferences` to automotive devices (`enforceAutomotiveDevice()`), so the per-uid default-network selection cannot be used on a phone. The design routes each app to the Tor network or to the normal default network through that selection. The gate is removed; `enforceOemNetworkPreferencesPermission()` and the validation stay, so only a component with `CONTROL_OEM_PAID_NETWORK_PREFERENCE` can set it. `enforceAutomotiveDevice()` stays defined and unused. |

Conflict surface on a new upstream release: `setOemNetworkPreference` (the `else` branch of the test-preference check).

## Resolver cache (NET-014, 2026-11-02)

The answer cache of the system resolver is shared by every uid of a network, and a cache hit sends no packet, so the steering rules and the exit daemon never see it: a real answer that another uid cached reached an app of class Masked, and a fake answer of the daemon reached an app that is not masked (`docs/architecture/network-exit-engineering-notes.md` of `freeholdos-foundation`, "The resolver cache is shared by every uid"). The patch makes the cache skip every name of the mask list. It was authored in the disposable repository `.worktrees/dnsresolver-cache/packages-modules-DnsResolver/` from a read-only copy of the two touched files, exported with `git format-patch`, checked with `git apply --check` and landed on the build server with `git am` on the new branch `freeholdos-2026100600` of `packages/modules/DnsResolver` (the project was at the unpatched upstream revision, detached). The library `libnetd_resolv` is shipped in the mainline module `com.android.tethering` in this tree; `com.android.resolv` is a manifest-only stub, so the module build of 2026-11-02 that named it did not package the change (measured on image `2026110202`: the tethering apex payload holds the mask-list code).

| Project | Base | Landed as | Subject |
| --- | --- | --- | --- |
| `packages/modules/DnsResolver` (`freeholdos-2026100600`) | `215bd613910d` (blobs `res_cache.cpp` `85a01ebe4132`, `Android.bp` `6ad4fa4c71a0`; sha256 `802dd214da0e...` and `b3aecffcdac4...` equal on the workstation and the server) | `6b183d27ca85` (tree `14535da36727`) | `patches/packages-modules-DnsResolver/0001`: resolver: never cache or serve an answer for a name of the exit mask list |

Why it diverges from upstream: `res_cache.cpp` asks the new `ExitMaskList` once per lookup and once per add; a query with a question name on the list gets `RESOLV_CACHE_SKIP` (the status that `ANDROID_RESOLV_NO_CACHE_STORE` already gives, so `res_send.cpp` neither reads nor adds) and `resolv_cache_add` refuses it with `-EPERM`. `ExitMaskList.h` and `.cpp` are new files (also in `resolver/src/`, equal to the landed files, sha256 `eff4cae0...` and `cd18ce20...`); `Android.bp` lists the `.cpp` in `libnetd_resolv`. The list is `/system/etc/freeholdos/exit-mask-list.tsv`, the file of the daemon, read once by a function-local static on the first query (3699 rows, 81 KB resident: 51 KB of domains and 8 bytes a row; the 119 KB of text is freed after the parse). Decisions: a missing or invalid list leaves the list empty and logs once at `WARNING`, because the daemon masks nothing without the same file, so the cache stays as it is; the matching is that of `masklist.rs` (the longest row decides, a protected row shields, one trailing dot, ASCII case, names outside letters, digits and hyphens never match); the file reader accepts every list the daemon accepts and may accept more (the name field is not read, a row of two fields is taken), so it can never leave the cache unprotected under a list the daemon runs with. SELinux needs no patch: `netd` is a `coredomain` and the policy of the phone has `allow coredomain system_file:file { execute getattr map open read }`; the list has the label `system_file` `[measured: sesearch on /sys/fs/selinux/policy and ls -Z of lynx 2026110201]`.

Conflict surface on a new upstream release: the two hooks in `resolv_cache_lookup` and `resolv_cache_add`, the include and the anonymous namespace before `resolv_cache_lookup`, and the `srcs` list of `libnetd_resolv`.
